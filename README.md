# SIXGUN

Requires Node.js 22 and npm. Run `npm ci`, then `npm run dev` (or double-click `start-preview.cmd` on Windows). Open the URL printed by the server. No AI API key is needed.

`npm run lint` checks TypeScript; `npm run build` creates the production client in `dist`. Regression checks are the `test:*` commands in `package.json`.

Mobile: the loading screen asks for landscape immediately. Layouts resize with the available viewport, browser bars, safe areas and aspect ratio. The floating top-right fullscreen button works throughout the game: tap to enter/exit, or hold for On/Off. When hidden, tap its 52px corner once to reveal it, then tap again to toggle. Supported touch browsers also lock landscape after the fullscreen gesture. On iPhone/iPad Safari without page fullscreen, the button explains Share → Add to Home Screen → open SIXGUN. The supplied manifest/icons enable a standalone web app without browser bars; rotate the device physically when orientation locking is unavailable. Fullscreen requests have a two-second recovery timeout, and optional orientation locking cannot keep the button disabled. Nuke uses left drag to move, right drag to aim, a single right tap to throw, and right double-tap to dodge. Single-tap throws wait briefly to distinguish double-tap dodges; there is no extra Dodge button. Nearby loose balls are picked up automatically. Gun Fight auto-fires at a visible target in both solo and custom rooms; double-tap the right side to jump.

Touch gameplay is paced at up to 60 FPS to avoid unnecessary 90/120 Hz heat and load. Desktop gameplay follows the available display refresh rate. Simulation uses elapsed time, including skipped display refreshes. Quality adapts only to sustained drops below 50 FPS, with a higher resolution floor; it does not lower clarity to chase 90/120 Hz. Actual FPS depends on the device, browser and power mode. Menus use 30 FPS to reduce heat. Add `?screen-test=1` to the preview URL to inspect common screen sizes.

The startup page uses actual animated 3D game characters in five rotating designs, sharing one WebGL canvas at up to 2× resolution. Gun Fight features an upper-body close-up holding the actual game weapon, with subtle atmospheric smoke. It automatically opens the game after the first rendered scene, landscape rotation on phones, and a short animation. The main-menu hero occupies its own column, with relaxed arms and an occasional small greeting; its camera fits that pose to show a larger character without clipping. Profile and customization previews render at up to 2× resolution. Gameplay defaults to up to 2× resolution with edge antialiasing, including phones. The default stays at or above 1.7× under sustained load, bounded by device DPR and a three-million-pixel framebuffer budget. Explicit lower quality presets remain available. Bloom, shadow detail and antialiasing cost adapt before large resolution changes. Add `?loading-preview=1` for a twelve-second showcase; the five dots select a design. Reduced-motion preferences stop character animation and automatic scene changes.

Volleyball uses continuous ball collision against the net, including ball radius and its top tape. Low shots rebound on the same side; high shots clear it. Local and remote players remain on their own side of the court, including during dives. Dark borders on both tapes keep the net visible on white maps. The mesh flexes visibly on impact with pinned posts; host snapshots carry each impact to remote players. Gun Fight is framed 3% closer and Nuke 5% wider; the shared HUD is 4 pixels lower. Voice controls show room availability, permission progress and speaking state.

Custom volleyball offers two-slot 1v1 and four-slot 2v2. Match results keep the current room and offer Back to room or an explicit Leave room action; the host opens the lobby for the next match. First-time name entry uses a compact, scrollable layout with a smaller keyboard view. Character springs use stable timing across refresh rates; final match snapshots use reliable delivery.

First-time controls include separate Gun Fight, Nuke and Volleyball tutorials, with Skip and replay through How to play. Smokey now uses spiked hair, a stern face, Midnight Leather clothing and a cigar with soft drifting smoke. Volleyball now uses the restored original lighting and off-white scenery on every court.

For a phone on the same Wi-Fi, replace `127.0.0.1` with the computer's LAN address. Microphone access requires HTTPS outside localhost. Obsolete source/assets are recoverable from ZIP backups in `.maintenance`; generated output and caches are excluded from source control.

For a temporary mobile HTTPS link, keep the production game server running on port 3001 and double-click `start-mobile-link.cmd`. It downloads the official Cloudflare client into the ignored local cache and starts a temporary public tunnel to that game server. Open its printed `https://…trycloudflare.com` URL on both devices, create/join the same room, then allow the microphone. Keep both the server and tunnel running; Ctrl+C in the tunnel window stops the public link. The launcher requires internet access. Actual phone voice and public WebSocket connectivity still need testing on the generated link.

Player name, appearance, selected modes/maps, gameplay/audio preferences, learned tutorials and tour progress are saved in browser storage. Tutorials appear once per game family and can be replayed from How to play. Custom-room tutorials use the actual room mode and appear before ready/start. Profile uses the visible viewport height, a compact mobile panel and a larger character preview. Saves belong to the same browser and website address; new temporary Cloudflare hostnames do not share them. Clearing site data/private sessions can remove saves.

Background music is an original synthesized stereo composition in `src/audio/musicComposition.ts`, with no third-party melody or recording. It defaults to a quiet 30% setting, starts after user interaction, and stops when paused, hidden or muted. A Web Worker builds the stereo loop away from gameplay; the cached audio buffer avoids continuous synthesis while playing. Older browsers without workers retain the incremental fallback. New soft net, dash and catch accents are synthesized; existing combat WAV samples remain unchanged. `npm run test:saved-quality-audio` verifies storage recovery, tutorial persistence, music headroom and loop lifecycle.

Custom volleyball predicts local shots immediately and waits for host acknowledgement before applying older snapshots. Monotonic round-trip probes estimate packet age without assuming synchronized phone clocks; ball prediction is bounded to 180ms and respects the net, while remote player extrapolation stops after 120ms. Scores remain host-owned. The follow camera tracks the controlled player in both position and aim, with checked sideline/back-line framing. All players should reload together after protocol changes. `npm run test:custom-volleyball` covers delayed/reordered events, collision-safe prediction and camera framing; real-device network conditions still need field verification.

Deploy on Vercel using [DEPLOYMENT.md](DEPLOYMENT.md). The website and multiplayer HTTP/WebSocket endpoint run in the same project, with shared room coordination in a MongoDB Atlas Free cluster. Leave `VITE_MULTIPLAYER_URL` empty for this setup. Custom Multiplayer opens the online connection; solo play and ordinary menus do not use the database. Direct WebRTC carries gameplay where available; cross-instance fallback is batched through MongoDB change streams with 50ms coalescing of replaceable movement. Free-plan usage limits apply and hosted resources must be connected before online rooms work. Optional Cloudflare TURN credentials stay on the server, and the client receives short-lived ICE configuration. Public MQTT is disabled by default and its library is loaded only if explicitly enabled. Settings → About contains the ArsDevS1 YouTube credit and Privacy Policy; `/privacy.html` also works without loading the game. `npm run test:vercel` checks concurrent joins and cross-instance room/event recovery with an in-memory MongoDB collection/change-stream boundary.

Low-end workload reductions: gameplay characters use 40% fewer triangles across all 13 default characters while retaining their proportions, outlines and full-detail profile previews. Static batching preserves indexed geometry (71% less buffer storage for the measured match character set than expanded vertices). Gun Fight/Nuke combine output conversion and color grading in one pass; touch devices avoid offscreen MSAA and use FXAA. Shadows use a 512px map on touch screens and refresh with each rendered character pose; sustained overload disables shadow maps while floor-anchored contact shadows remain. Default framebuffer clarity and volleyball lighting are preserved. The initial client bundle is about 330 KB smaller before compression because the disabled MQTT library no longer loads at startup. `npm run test:low-end` checks real model geometry, simulated render/pacing behavior and actual worker synthesis; it does not measure phone FPS.

Fixed world scenery now skips repeated world-matrix traversal in every game family. Rigid parts inside moving vehicles/clouds are batched while propellers stay animated. Across the six Volleyball courts, additional batching reduces scenery meshes from 1,077 to 688 (36%), with unchanged geometry bounds. Elastic net waves reuse per-impact spatial weights instead of recomputing exponentials per vertex per frame. Net collision covers descending top-tape contacts, rounded corners, fast shots and overlap recovery, using the same 0.44/0.66 ball radii for gameplay and network prediction. Straight vertical tape landings spill into the adjacent court rather than bouncing in place. The ball squash spring remains stable on slow frames. Gun Fight elimination confirmation uses a compact skull/ELIMINATED badge and a 600ms animation, with a reduced-motion fade. These checks establish correctness and reduced CPU/draw work; real phone FPS and the cost of smoother shadow updates still require device verification.

Batched scenery and fixed character parts reuse their local transform matrices each frame. Animated parents still move normally, and bounds queries refresh world transforms before measuring character sizes, camera framing and ragdolls. This reduces repeated CPU work without changing resolution, materials or geometry. Nuke now has a slightly wider reticle assist region, bounded throw correction, stronger moving-target lead and a 13% larger hit radius; dodge and invulnerability timing remain the same. `npm run test:polish` and `npm run test:response` cover the transform/framing behavior and forgiving throws across refresh rates.
